# Overview
This PRD covers a text-only rebrand from "Univer" to "Strique" across user-facing content. The goal is to replace visible occurrences of the brand in UI strings, page titles, documentation, and metadata without changing package scopes/imports, code identifiers, styles, or build settings.

# Core Features
- Text replacement rules and casing policy for the new brand
- Clear exclusions to avoid breaking imports, URLs, or code
- Repeatable search/replace process with preview and verification steps

# User Experience
- Users see "Strique" (and "Strique Sheets" where applicable) everywhere text is presented
- Application visuals, behavior, and performance remain unchanged
- No breaking changes to public APIs, package names, or import paths
</context>

<PRD>
# Technical Architecture
This initiative is limited to content/strings. No refactors, no visual changes, and no package scope changes.

- Scope of Text Changes
  - Replace brand strings in user-facing files: `.html`, `.md`, `.ts`, `.tsx`, `.json` where they render text or metadata
  - Update page/document titles, tooltips, toasts, menu/item labels, and Storybook/demo titles
  - Update README variants and docs under `docs/`

- Strict Exclusions (do not change)
  - `@univerjs/*` package names, imports, and code identifiers
  - URLs and CDNs containing `univerjs` or existing domains
  - Historical references in `CHANGELOG.md` (unless explicitly requested)
  - Legal attributions of third-party software

- Search/Detection
  - Use case-insensitive search for: `Univer`, `UNIVER`, `Univer Sheets`, `UniverJS` (only when used as visible brand text)
  - Exclude: `node_modules/`, `dist/`, coverage outputs, generated artifacts

- Replacement Rules
  - `Univer Sheets` → `Strique Sheets`
  - `Univer` → `Strique`
  - `UNIVER` → `STRIQUE`
  - `UniverJS` (visible brand text only) → `Strique`
    Note: Do not modify `@univerjs/*` imports or code symbols.

- Verification
  - Run unit/snapshot tests; update snapshots that assert brand text
  - Manual spot-check high-value files: `examples/public/index.html`, `examples/src/**/*`, Storybook configs, `README*.md`, `docs/**/*`
  - Re-run global search to confirm no lingering visible occurrences except in excluded areas

# Development Roadmap
- Phase 1 — Inventory (Read-only)
  - Generate a findings file of all candidate occurrences
  - Tag and separate exclusions (imports, URLs, changelog history)

- Phase 2 — Define Replacement Map
  - Lock the casing and phrase rules (above)
  - Confirm exclusions with stakeholders

- Phase 3 — Apply in Priority Areas
  - Update HTML titles/meta in `examples/public/**`
  - Update visible UI strings in `examples/src/**/*.{ts,tsx}`
  - Update Storybook/demo/UI package strings if present
  - Update top-level docs: `README*.md`, `docs/**/*`

- Phase 4 — Tests & Snapshots
  - Run tests; update snapshots where branding is asserted

- Phase 5 — Final Sweep & Sign-off
  - Re-run search, validate exclusions not modified
  - Collect sign-off from stakeholders

# Logical Dependency Chain
1) Inventory (read-only) → 2) Replacement rules → 3) Apply updates → 4) Tests/snapshots → 5) Final sweep/sign-off

# Risks and Mitigations
- False positives in code identifiers/imports → Maintain strict exclusion lists; review diffs
- Internationalization copies (non-English READMEs/docs) missing updates → Include all `README-*.md` and `docs/` locales in search
- Snapshot churn → Update only expected snapshots; document rationale
- Legal/historical mentions → Leave changelog entries and third-party attributions intact unless approved

# Appendix
- Suggested Commands (macOS BSD sed)
  - Preview: `rg -n -i -g '!**/node_modules/**' -g '!**/dist/**' 'Univer|UNIVER|Univer Sheets'`
  - Apply (exact phrase first):
    - `sed -i '' 's/Univer Sheets/Strique Sheets/g' <files>`
    - `sed -i '' 's/Univer/Strique/g' <files>`
    - `sed -i '' 's/UNIVER/STRIQUE/g' <files>`
  - Post-check: re-run ripgrep and manual review

- Acceptance Criteria
  - All user-facing occurrences of "Univer"/"Univer Sheets" replaced with "Strique"/"Strique Sheets"
  - No changes to `@univerjs/*` imports, URLs, or code identifiers
  - Tests and snapshots pass (with expected snapshot updates)
  - Docs and examples reflect the new brand text consistently
</PRD>
